What is event binding and property binding => Binding means connecting data (state/props) to UI elements or event handlers.
👉 Property Binding: Binds state/props to a UI element’s attributes.
    eg: A text input whose value is controlled by state.
        /* 
            const [name, setName] = useState("John");
            <input type="text" value={name} onChange={(e) => setName(e.target.value)} />
        */
        Here, the input’s value is bound to the name state. Any change updates the state, and the UI updates automatically.
👉 Event Binding: Binds functions to handle user interactions like clicks, input changes, etc.
    eg: A button that increases a counter when clicked.
        /*
            const [count, setCount] = useState(0);

            function handleClick() {
                setCount(count + 1);
            }

            return ( <button onClick={handleClick}>Increase</button> );
        */
        Here, clicking the button triggers handleClick(), which updates the count state.

What is Virtual DOM =>
    Virtual DOM is a fast, optimized copy of the real DOM that helps React update the UI efficiently!
    Why is Virtual DOM Needed => Problem with Real DOM:
        => Updating the real DOM is slow because it repaints the entire UI for every small change.
    Solution => Virtual DOM:
        => React creates a virtual copy of the DOM, compares changes, and updates only the necessary parts, 
        making it super fast! 

    How Virtual DOM Works (Step-by-Step)
    1️⃣ React creates a Virtual DOM copy when the app loads.
    2️⃣ User interacts (e.g., clicks a button).
    3️⃣ React updates the Virtual DOM instead of the real DOM.
    4️⃣ Diffing Algorithm finds changes between the old & new Virtual DOM.
    5️⃣ React updates only the changed parts in the real DOM.

=================================================================================================================================
How Virtual DOM optimizes the performance of the application => Virtual DOM helps React update only the changed parts 
    instead of reloading the entire UI, making apps super fast & efficient!
    => Key Benefits of Virtual DOM in Performance Optimization
    ✅ Faster UI updates (avoids full re-renders).
    ✅ Efficient memory usage (uses a lightweight copy).
    ✅ Smoother experience (only necessary parts update).
    ✅ Less workload on the browser (better performance).

How do you read the url parameters and queries during routing in react => In React, you can read URL parameters (like /user/1) 
    and query strings (like ?search=hello) when using React Router.
    => Read URL Parameters (Dynamic Routes)
        => Define the Route => Define the route with parameters using :paramName
        eg: <Route path="/user/:id" component={UserPage} />
        => Read the Parameter: => Use useParams hook to access the parameter in your component.
        eg: import { useParams } from 'react-router-dom';

            function UserPage() {
                const { id } = useParams(); // Reads the 'id' parameter
                return <h1>User ID: {id}</h1>;
            }

    => Read Query Parameters (e.g., ?search=hello)
        => Define the Route: => You don’t need to define query parameters in the route, just use the path.
        Eg: <Route path="/search" component={SearchPage} />
        => Read the Query Parameter: => Use useLocation hook to access query parameters.
        Eg: import { useLocation } from 'react-router-dom';

            function SearchPage() {
                const location = useLocation();
                const query = new URLSearchParams(location.search); // Parses query string
                const searchTerm = query.get('search'); // Gets the 'search' query parameter
                
                return <h1>Search Term: {searchTerm}</h1>;
            }
    
    URL Parameters: Use useParams() to read dynamic values in the URL (/user/:id).
    Query Parameters: Use useLocation() to read query strings (?search=hello).

Explain the lifecycle of react Application & What are the different types of lifecycle phases in react 
    => The lifecycle of a React application refers to the different stages a component goes through from the moment it is
    created to the moment it is removed. In React, this lifecycle is divided into three main phases: Mounting, Updating, and Unmounting.
    => Mounting: Component is created and added to the page (e.g., constructor(), render(), componentDidMount()).
    => Updating: Component gets updated due to changes in state or props (e.g., shouldComponentUpdate(), render(), componentDidUpdate()).
    => Unmounting: Component is removed from the page (e.g., componentWillUnmount()).
    
    This lifecycle lets React manage updates and performance efficiently!

What is higher order components => A Higher-Order Component (HOC) is a function that takes a component and returns a new 
    component with additional functionality or enhanced behavior. It’s a pattern used to reuse component logic in a clean way.
    => How Does it Work?
        => HOCs do not modify the original component. Instead, they wrap the component and add extra features to it.
        => HOCs can be used for things like adding authentication, fetching data, logging, or adding lifecycle methods.
        Eg: Create a Higher-Order Component:
            function withLoadingSpinner(Component) {
                return function WithLoadingSpinner({ isLoading, ...props }) {
                    if (isLoading) {
                        return <div>Loading...</div>;
                    }
                    return <Component {...props} />;
                };
            }

        Eg: Use the HOC:
            function MyComponent({ data }) {
                return <div>Data: {data}</div>;
            }
          
            // Wrap MyComponent with the HOC
            const MyComponentWithLoading = withLoadingSpinner(MyComponent);
            
            // Use the new component with the loading functionality
            function App() {
                return <MyComponentWithLoading isLoading={true} data="Hello" />;
            }

What is lazy loading & suspense in react => Lazy loading and Suspense are techniques used to optimize performance in React 
    by loading components or data only when needed, rather than loading everything upfront. This helps your app load faster, 
    especially when dealing with large components or libraries.
    => Lazy Loading
        =>  What is it?
            => Lazy loading allows you to load a component only when it's needed (usually when it's displayed on the screen), 
            instead of loading all components when the app starts.
        =>  How does it work?
            =>  You can use React.lazy() to dynamically import a component when it's required, so the app doesn't load 
                unnecessary code upfront.
        =>  eg
                import React, { Suspense } from 'react';
                const LazyComponent = React.lazy(() => import('./LazyComponent')); // Lazy load this component
        
                function App() {
                    return (
                        <div>
                        <h1>Welcome to my App</h1>
                        <Suspense fallback={<div>Loading...</div>}>  {/* Fallback UI until LazyComponent is loaded */}
                            <LazyComponent />
                        </Suspense>
                        </div>
                    );
                }
        =>  Why use it?
            =>  Lazy loading helps your app load faster by only loading the parts of the app that the user actually needs 
            right now.
    =>  Suspense
        => What is it?
            =>  Suspense is a React feature that helps manage loading states when lazy-loading components, async data, or 
            anything that requires waiting to load.
        
        => How does it work?
            => Suspense allows you to define a "fallback" UI (like a loading spinner or message) that will be shown while 
            the lazy-loaded component or async data is being fetched.

        => Example with Lazy Loading:
            const LazyComponent = React.lazy(() => import('./LazyComponent'));

            function App() {
              return (
                <div>
                  <Suspense fallback={<div>Loading...</div>}>
                    <LazyComponent />
                  </Suspense>
                </div>
              );
            }
        => Why use it?
            => Suspense makes handling loading states easier by allowing you to define exactly what should be shown while 
            waiting for components to load or data to be fetched.

What are controlled and uncontrolled form inputs, which is most efficient in usage => In React, form inputs can be controlled 
    or uncontrolled, based on how the data is managed.
    => Controlled Components (Recommended & Efficient)
        => React controls the input value using state.
        => Changes in the input are handled by useState() or this.state.
        => eg:  import { useState } from 'react';
                function ControlledForm() {
                    const [inputValue, setInputValue] = useState('');
                    return (
                        <div>
                            <input type="text" value={inputValue} // React controls the input
                            onChange={(e) => setInputValue(e.target.value)}  /> // Updates state
                            <p>Typed: {inputValue}</p>
                        </div>
                    );
                }

        => Why Use Controlled Components?
            ✅ Single source of truth (input value is always in React state).
            ✅ Easier to validate, modify, or manipulate input data.
            ✅ Recommended for most cases in React applications.
        
    =>  Uncontrolled Components (Less Efficient)
        =>  React does NOT control the input value.
        =>  Instead, the input holds its own value, and we access it using useRef() or document.getElementById().
        => Example  import { useRef } from 'react';
                    function UncontrolledForm() {
                        const inputRef = useRef(null);
                        const handleSubmit = () => {
                            alert(`Typed: ${inputRef.current.value}`);
                        };
                        
                        return (
                            <div> <input type="text" ref={inputRef} /> {/* React doesn’t control the input */}
                            <button onClick={handleSubmit}>Submit</button> </div>
                        );
                    }
        =>  Why Use Uncontrolled Components?
            ✅ Useful when working with third-party libraries or existing forms.
            ✅ Slightly better performance for very large forms.
            ❌ Not ideal for React apps since state is not managed effectively.
